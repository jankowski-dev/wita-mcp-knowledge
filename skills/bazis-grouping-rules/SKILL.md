# Правила структурирования проектов в «Базис-Мебельщик»

При создании или редактировании мебельных модулей (вручную, скриптом или через
WITA MCP) строго соблюдай правила ниже. Их игнорирование ломает спецификации,
чертежи и автоматизацию.

## 1. Блоки (группировка)

- **Блок = модуль.** Каждый законченный узел (тумба, шкаф, пенал) — один блок
  (`Alt+1`).
- **Состав блока:** панели корпуса, фасады, вся крепёжная фурнитура
  (конфирматы, минификсы, шканты), направляющие. Фурнитура не остаётся вне
  блока модуля.
- **Запрет плоской структуры:** сотни отдельных панелей в корне сцены не
  оставляем — это ломает вывод чертежей.

## 2. Именование (критично для скриптов и парсинга)

Строгие префиксы, чтобы агент/скрипт фильтровали объекты программно:

| Префикс | Что это | Пример |
|---|---|---|
| `MOD_` | блок-модуль | `MOD_Тумба_01` |
| `PUR_` | покупное изделие | `PUR_Мойка_500` |
| `ACC_` | отдельная фурнитура (вне блока) | `ACC_Петля_01` |
| `FAS_` | фасад | `FAS_Дверь_01` |

- **Пробелы в именах запрещены** — только нижнее подчёркивание `_`.
  (Дополнительный плюс: имена без пробелов безопасно ходят в `path` MCP-операций.)

## 3. Слои

Слои разделяют объекты **по материалам/типам обработки**, а не по модулям:

- `Корпус_ЛДСП`, `Фасады_МДФ`, `Стекло_Зеркала`, `Фурнитура`.
- Все панели корпуса — на слое `Корпус_ЛДСП` и т.д. Это даёт автоматическую
  сортировку при выводе спецификаций.

## 4. Покупные изделия

Сложный покупной механизм (подъёмник, мойка, сушка) группируй через
**«Создать покупное изделие»**, а не обычным блоком — иначе смета разобьёт его
на детали и себестоимость посчитается неверно.

## 5. Параметризация (эластичные блоки)

Типовые модули (стандартные базы, шкафы) — **эластичные блоки** с параметрами
(ширина/высота/глубина) во встроенном редакторе: при изменении габаритов
наполнение перестраивается само. Не плоди каждый размер вручную.

## 6. Алгоритм агента при проектировании

1. Создать панели (имена по префиксам, без пробелов).
2. Расставить фурнитуру.
3. Выделить панели + фурнитуру модуля.
4. Создать блок, присвоить имя `MOD_...`.
5. Распределить объекты по слоям (материалам).
6. Типовой модуль — параметризовать (эластичный блок).

## 7. Реализация через WITA MCP (текущий статус)

- **Имена** — задаются сразу при генерации: `add_panel(name: "FAS_Дверь_01")` и
  т.п.; путь в операциях — без пробелов.
- **Блоки/слои** — отдельных MCP-операций пока нет. В старом API для блоков
  просматривается `AddAssembly("MOD_...")` (требует probe перед применением);
  слои в старом JS-API не документированы. До появления операций: структура
  фиксируется именами, а выделение в блок/слои пользователь делает в программе.
- **Крепёж** (`mount_furniture`, `add_butt`) создаётся движком с автоименами —
  ренейм не практикуется; группировка обеспечивается принадлежностью модулю.
- **Проверка соблюдения правил:** `get_model_summary` + фильтр по префиксам
  (`MOD_`/`PUR_`/`ACC_`/`FAS_`), `list_materials` — по материалам/слоям.

## 8. Легаси-проекты

Существующие модели со старыми именами (`B1-SideL`, `MCP-A`, …) не
переименовываются без явной просьбы пользователя: переименование — отдельная
операция с подтверждением. Новые объекты и генерации — сразу по этим правилам.
