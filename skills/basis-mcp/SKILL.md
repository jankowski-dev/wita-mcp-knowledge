# Работа с WITA MCP Server

MCP-сервер `basis` — «руки» агента в БАЗИС-Мебельщике. Обмен идёт через
файловый ящик `C:\Users\Public\basis-mcp` с резидентным worker-скриптом.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `basis_status` | жив ли worker, версия, очередь, рекомендация |
| `basis_execute` | выполнить операцию из белого списка (op, params, timeoutMs) |
| `basis_model_summary` | дерево модели (maxDepth, includePanelInfo) |
| `basis_probe_report` | отчёт диагностического probe-скрипта |

## Жизненный цикл worker'а (важно)

1. Пользователь **один раз** за сессию БАЗИС: «Скрипты → 0_BasisMCP_worker».
2. Дальше всё автоматически: очередь исполняется таймером каждые ~2 с.
3. Сессия умирает при: перезапуске БАЗИС, ESC, запуске другого скрипта,
   интерактивном выборе материала в пикере.
4. **Очередь не теряется**: при следующем запуске worker исполняет backlog сразу.

## Порядок действий

1. Перед работой — `basis_status`. Если `not-running`/`worker-idle-waiting` —
   попроси пользователя запустить worker (ровно одно действие).
2. Операции шли через `basis_execute`. Батчи 50–150 команд за тик — нормально.
3. После мутаций проверяй результат: `basis_model_summary`, `object_info`.
4. Перед массовыми изменениями — `batch_set_material` с `dryRun: true`.
5. Не сохраняй модель за пользователя, не удаляй чужие объекты без подтверждения.

## Правила правки модели (probe-подтверждённые)

- **Обёртки объектов умирают на `Commit()`**: после каждого коммита объект
  ищем заново по пути/имени (`basisMcpRefetchByName`). Чтение свойств с
  «мёртвой» обёртки → `Invalid pointer operation` (инцидент v0.5.7).
- Правка **существующего** объекта — сначала маркер `Undo.Changing(obj)`
  (в worker'е это внутренний marker, оп `object_move`/`resize_panel` делают
  это сами).
- Верификация правок — **только `Position` и `ContourWidth/Height`**;
  `gmin/gmax` локальные и после правок не пересчитываются.
- Контуры панелей всегда **0-based** (`resize_panel` строит прямоугольник от
  (0,0) — якорь менять не нужно).
- `object_move` работает и на панелях, и на смонтированной фурнитуре
  (`Translate()`). Для mounted-объектов путь — имя по первому матчу: при
  дубликатах работай по индексам.
- **Удаление по имени при дубликатах берёт первый матч** (реальный инцидент:
  подчистка тестов сняла кухонный «Евровинт 6х50» вместо тестового). Схема:
  `basis_model_summary` → индекс → `delete_object` с числовым путём (`[216]`).
- Копирование — recreate-стратегия (`copy_object` v0.6.1): `Clone()` живёт
  только до коммита. Кромки в копию не переносятся — `add_butt` отдельно.
- Свойства (`Name/MaterialName/Thickness`) пишутся **до** коммита — после
  коммита запись уходит «в никуда» (обёртка перерождается).

## Быстрая диагностика

| Симптом | Причина | Решение |
|---|---|---|
| `unknown op` в результате | старая версия worker'а | перезапустить worker |
| `timeout` | worker мёртв / модальный диалог | закрыть диалог, перезапустить worker |
| heartbeat старый, mode `armed` | сессия уснула | перезапустить worker |
| `object not found by path` | имя/индекс неверны | перечитать дерево |

## Безопасность и расширение

- Исполняется **только белый список операций** — произвольный код агент в БАЗИС
  не передаёт.
- Новая операция: обработчик в `BASIS_MCP_HANDLERS` (`bridge/basis_mcp_worker.js`)
  → `node --check` + ASCII-контроль → деплой (`tools/install-worker.ps1`) →
  перезапуск worker'а пользователем → документация в `docs/OPERATIONS.md` (репо
  кода) и в этом скилле.
- Не сохранять модель за пользователя; не удалять чужие объекты без подтверждения.

## Полный список операций

Смотри репозиторий кода: `wita-mcp-server/docs/OPERATIONS.md`.
Ключевые: `add_panel`, `add_butt`, `mount_furniture` (режимы `plane`/`between`),
`open_furniture`, `rename_object`, `delete_object`, `batch_set_material`,
`object_info`, `model_commit`, `list_materials`, `object_move`, `resize_panel`,
`copy_object`, `add_cut` (мультипойнт), `holes_info`.
